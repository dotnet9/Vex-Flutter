# 演示与自定义标题栏验证（2026-10-17）

当前仍不能认定达到原型的 98%。本轮补全正文、大纲、导图共用的演示流程，并纠正原生对照测试未采用正式窗口初始化的问题。测试通过数量、背景像素相似度都不作为产品还原率。

## 原型与实现

- 桌面视图菜单、手机更多菜单提供演示入口，桌面支持 F5。标题开始一页，`---` 显式分页；围栏中的标题与分割线不分页。
- 演示顶栏提供大纲、正文 / 导图切换和退出；底栏提供前后页、页码、缩放和进度。大纲直接选择章节，手机作为完整内容区域展示。
- 正文长页按块虚拟化，可以滚动。导图翻页聚焦相应节点，单击节点选择章节，双击回到正文；支持平移、缩放与全图适配。
- 大图总览直接绘制节点卡片，聚焦或放大后恢复完整文字与节点交互。二维缩放独立计算，避免未缩放的 Z 轴让小于 100% 的倍率显示错误。
- 演示使用独立控制器和只读导图，不允许重排或修改原文。退出保留工作区布局、编辑选区及滚动位置。
- Windows 进入原生全屏，退出恢复普通或最大化状态；原型在浏览器支持时请求全屏。
- 桌面与自适应原型共用 `presentation.js` / `presentation.css`；四种语言的演示控制文案由实际 ARB 生成。

## 标题栏修正

正式应用原来已有隐藏系统标题栏的配置，但性能及视觉测试使用了不同的初始化入口。因此之前出现系统标题栏的测试画面不能代表正式自定义窗体，也不能据此进行完整外观验收。

现在正式应用、视觉对照、长文档压力测试和窗口演示测试复用 `initializeDesktopWindow`，隐藏系统标题及系统窗口按钮。自定义标题栏从客户区顶部开始，高 40 px；最小化、最大化 / 还原、关闭由应用控件提供。空白区拖动、双击最大化 / 还原，最大化图标跟随原生状态更新。

标题栏增加四语言菜单；主题按钮按浅色、深色、跟随系统循环，配色选中环与色点分离，避免选中态改变色点大小。窗口按钮为 42×39 px 的矩形命中区域，关闭悬停使用红色，普通浮层仍使用共用的 32 px 关闭按钮。

## 验证边界

原生测试 `presentation_window_test.dart` 检查最大化进入 / 退出演示三轮，正文及导图翻页，F5 / Esc，以及普通窗口的位置、宽高恢复（误差不超过 1 px）。每轮检查布局、源文与脏状态。截图和状态记录与本文同目录。

最终回归：`dart analyze` 无问题，应用 44 项、导图包 7 项通过；原生窗口测试通过。[窗口状态记录](presentation-window-states.json) · [最大化自定义标题栏](custom-titlebar-maximized.png) · [正文演示](presentation-markdown.png) · [导图演示](presentation-mindmap.png)。

最大化窗口的六份长文档、六轮切换与 24 次演示往返共 756 项通过，详细耗时、内存与失败记录见[压力测试](最大化与导图演示压力测试.md)。

Windows Release 已由同一源码重新构建并运行，实际画面确认应用图标、自定义标题栏及最大化按钮。补充手工操作中，桌面自动化工具反复返回 `Computer Use helper already has an active request`，且截图出现其他应用覆盖；本次 Release 的完整演示往返和关闭操作未取得可判定结果，不计入通过。检查本次启动以来的 Windows Application 1000 / 1001 事件未发现匹配应用的故障记录，进程查询仍为响应状态；这不能代替关闭或演示验收。

控件回归覆盖 500 章节离屏聚焦、分页边界、围栏、Setext、空文档、键盘隔离及退出后选区 / 滚动恢复；三个屏幕尺寸、四语言、深浅主题检查最大字号和控件布局。导图包另检查 1500 节点全图适配及回到可读节点。

## 98% 的验收缺口

需要在相同窗口客户区、DPR、文档、字体、语言、主题、布局与滚动位置下，分别检查标题栏、工作栏、侧栏、正文、状态栏、浮层和演示。先核对矩形、基线、间距、字号及按钮命中区域，再查看前景差异图；不能让空白背景掩盖控件与文字差异。

现有对照截图只覆盖部分布局。完整的八布局、六排版、八配色、深浅模式与三类屏幕矩阵仍未验收；复杂行内编辑、公式、图表、代码高亮与跨块选择仍有实现或验证缺口。它们完成前不发布“已还原 98%”的结论，也不将当前预览构建标为正式发行版。
