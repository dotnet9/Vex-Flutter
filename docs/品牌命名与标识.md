# 品牌命名与标识

统一品牌为「维刻 Vex」，slogan 为「写下想法，看见脉络」。

## 大小写约定

Dart 标识符区分大小写。Windows 文件系统通常不区分路径大小写，但 Linux、Android 及 CI 构建环境不能依赖这一行为。

| 用途 | 命名 |
| --- | --- |
| 品牌、标题、分发安装包 | `Vex` / `维刻 Vex` |
| Dart 类型 | `VexApp` 等 UpperCamelCase |
| Dart 包、文件、目录、Linux 命令 | `vex`、`vex_editor`、`vex_markdown_core`、`vex_mindmap` |
| 原型页面、Windows 安装脚本 | `Vex.html`、`Vex-Adaptive.html`、`Vex-Installer-*.html`、`Vex.iss` |
| 环境变量与 JavaScript 全局常量 | `VEX_*` |
| Android namespace / applicationId | `com.codewf.vex`，preview 使用 `.preview` 后缀 |
| iOS / macOS Bundle ID、Linux 应用 ID | `com.codewf.vex` |
| Windows / Linux 可执行文件 | `vex.exe` / `vex` |
| macOS 应用与可执行文件 | `Vex.app` / `Vex` |

## 安装与数据边界

本次统一包括正式平台标识，经确认接受新的应用身份。Android 新包不会覆盖改名前的应用，两者可并存；旧应用的设置、最近文件和恢复草稿不会自动转移。iOS、macOS、Linux 的应用标识同样已更新，不能假设旧设置目录会被新应用复用。

更新前先在旧应用中将未保存内容另存为 Markdown，再在新应用中打开原文件并按需重新配置偏好设置。确认文档无误后再卸载旧应用，不要先卸载再尝试找回恢复草稿。普通 Markdown 文件本身不改名、不转换、不删除。

Windows 保留既有安装升级 GUID 和 `Vex` 安装目录；程序文件名及 Markdown ProgID 分别统一为 `vex.exe` 和 `Vex.Markdown`。如需文件关联，安装时勾选相应选项，并按 Windows 系统要求选择默认应用。

内部包及公开 Dart 入口已一并更名，宿主项目需要同步修改依赖与 `package:` 导入，没有保留旧包名别名。原型入口也已更名，需要从 `design/index.html` 打开新链接；旧原型本地偏好不会迁移。

历史验证文档中的源码路径和品牌引用已统一为当前名称；旧版本的二进制产物、历史提交、测试证据和本机外部 SDK 不会被改写。版本号仍为 `0.2.2+4`，本次名称统一不自动创建新 tag 或 Release。

## 防止回流

`scripts/tests/test_brand_contract.py` 检查当前源码文件名、内容、内部包入口与平台身份；CI 会运行该检查。构建缓存、签名材料、Git 历史及忽略的本地证据不属于源码扫描范围。
