# 贡献指南

感谢参与维刻 Vex。当前仍是开发版本，不将浏览器原型、控件测试或 CI 构建通过视为所有平台验收完成，实际进展以仓库文档与测试记录为准。

## 开发阶段兼容策略

- 当前按全新开发处理，只维护当前设置格式、内部接口、命令和目录结构；不为旧开发版本保留迁移分支、旧字段读取、废弃 API 或命令别名。
- 结构调整时同步更新调用方、测试和文档，不增设兼容层。稳定后再明确版本与数据迁移策略，目前不承诺跨版本设置、草稿格式或降级兼容。
- 首次启动默认值、损坏数据检查、原子保存、恢复备份、跨平台适配和外部协议 / Markdown 格式支持不是历史兼容逻辑，不以清理兼容代码为由删除。
- 变更不得主动删除或覆盖用户的 Markdown、附件和现存数据目录；开发测试前另行备份重要内容。

## 开发环境

使用根目录 `.flutter-version` 固定的 Flutter stable 版本，以及该版本附带的 Dart。仓库采用 Pub workspaces，保留并提交根目录 `pubspec.lock`，不要为各包另建锁文件。

```powershell
python scripts/sync_builtin_documents.py
flutter pub get --enforce-lockfile
flutter analyze --no-pub
```

Windows 本机打包优先使用根目录 `publish_win-x64.bat`，它会自动补齐缺失的插件链接，无需额外修改插件清单。直接调用 Flutter 遇到链接权限问题时，手动绕过及还原步骤见 [本机打包安装升级与数据备份](07-本机打包安装升级与数据备份.md)。

应用入口位于 `apps/vex/lib/main.dart`。桌面在应用目录运行 `flutter run -d windows`，macOS、Linux 替换设备名称。Android 必须显式选择开发 flavor：

```powershell
cd apps/vex
flutter run --flavor preview -d <设备编号>
```

Android 工具链与签名边界见 [Android 构建](Android构建.md)。使用 preview 身份隔离开发测试，不要用 production 包名试验破坏性数据操作，也不要提交私钥、密码、令牌、个人文档或本地路径配置。

## 代码边界

- `apps/vex` 负责应用界面、平台服务与工作流，沿用现有 View/ViewModel、Repository/Service 分层和 provider。
- `packages/vex_markdown_core` 保持纯 Dart；编辑器和导图通过 controller、callback 接入宿主，不反向依赖应用。
- Markdown 原文是唯一数据来源；修改必须保留 CRLF、Unicode、选区位置和统一撤销历史。输入法候选期间避免改写缓冲，异步操作必须验证文档及版本是否仍有效。
- 优先复用现有主题令牌、本地化、图标和控件；支持键鼠、触控、焦点、语义和减少动态效果。界面文案维护 ARB，并运行 `flutter gen-l10n`。
- 只提交与任务相关的变更，避免无关格式化、生成物或依赖升级。保留他人的未提交修改。

## 验证

在各目录运行对应测试：

| 目录 | 命令 |
| --- | --- |
| `packages/vex_markdown_core` | `dart test --coverage=coverage` |
| `packages/vex_editor` | `flutter test --no-pub --coverage` |
| `packages/vex_mindmap` | `flutter test --no-pub --coverage` |
| `apps/vex` | `flutter test --no-pub --coverage` |
| 仓库根目录 | `python -m unittest discover -s scripts/tests -v` |

修改 Dart 后运行 `dart format`，提交前使用 `git diff --check`。CI 对已跟踪的 Dart 文件执行只读格式检查，并保存覆盖率文件；测试数量和覆盖率都不是视觉、性能或原生兼容性的验收结果。

原型契约检查无需第三方 Node 依赖。运行 `design/scripts/verify*.cjs` 下的全部脚本；脚本检查数据与交互契约，不是浏览器像素对比。`design/scripts/browser-*.cjs` 是可选的离屏浏览器检查，需要已有 Playwright 环境和运行中的预览服务，运行方式见 [原型设计](design/原型设计.md)。界面改动应附同尺寸、同字体、同场景的原型及原生截图，注明主题、缩放、语言与平台；未经完整对照不得宣称达到 98%。

原生集成测试位于 `apps/vex/integration_test`。例如在应用目录执行：

```powershell
flutter test --no-pub integration_test/typing_test.dart -d windows
flutter test integration_test/touch_selection_test.dart --flavor preview -d <Android设备编号>
```

合成中文候选、模拟触控和窄窗口检查不能替代系统输入法、物理设备及软键盘验收。请明确列出未测项目。

## 资源与发布

品牌源为根目录 `logo.svg`、`logo.png`、`logo.ico`，通过 `python scripts/sync_brand_assets.py` 同步，需要 Pillow。不要手动修改派生图标。原型与应用的内置 Markdown、版本信息及第三方许可通过现有同步脚本维护。

所有说明文档的正文统一维护在 `docs`；其他目录的 README、CHANGELOG 等入口只链接到对应正文，不维护副本。目录约定见 [文档导航](文档导航.md)。第三方许可证、NOTICE 等法律声明仍随原资源保留。

只修改 `docs/鸣谢.md` 和 `docs/更新日志.md` 两个内置文档源文件，然后运行 `python scripts/sync_builtin_documents.py`，同时生成原型离线数据和应用资源。生成物被 Git 忽略，不手动编辑或提交。CI、完整打包入口与原型预览服务会自动生成；直接打开 HTML 或手动运行 Flutter 前需要运行该命令。`--check` 可只读核对生成物。修改应用版本或依赖后运行 `python scripts/sync_project_info.py`，同步 MCP 版本、原型信息和主要依赖许可。

应用更新日志使用 `## V版本号（YYYY-MM-DD）`，同一天合并为一节。每个版本号下只能有无序列表，每项使用 `😄[新增]-描述`、`🔨[优化]-描述` 或 `🐛[修复]-描述`，不添加分类标题、说明段落或开发流水账；已知限制放在对应 Release 说明和验收文档中。

安装包与标签流程见 [安装包与自动发布](安装包与自动发布.md)。iOS IPA、HarmonyOS HAP 在签名与适配条件具备前暂缓发布，不使用未签名文件或便携压缩包代替安装包，不绕过发布校验。

提交和 PR 应说明修改目的、验证命令、实际测试平台及剩余限制。安全问题按照 [安全政策](安全政策.md) 私下报告，不附在公开 Issue 或 PR 中。
